# Brief: step 1, build the app inline

Plan: `.scratch/1-run-officium-as-an-oculus-root-app/plan.md`, step 1. Rules: `.agents/change-standard.md`, including its section "Officium rules". Executor: inline, in the main checkout, no worktree, no commit (plan Rulings A and B). The step's work is the uncommitted working tree against `HEAD`: `git diff` for changed files and `git ls-files --others --exclude-standard` for new ones, excluding `.agents/` and `.scratch/`.

## Goal of the step

Officium's interface runs as an oculus root app, built by `npm run build:oculus` into the git-ignored `.oculus/apps/officium/`, reusing the data, reader and view code of the other builds.

## Requirements the step is judged on

1. `npm run build:oculus` writes `.oculus/apps/officium/` with `app.yml` (name `officium`, `bridge: 1`, no `reads`, `writes` or `connects`), a relative-path `index.html` with no inline script, one script and one style file.
2. The folder is ignored by Git, Prettier and ESLint.
3. The library is read through `oculus.fs.readDirectory` and `readFile` from `rituals/`, else `examples/rituals/`, in both document formats (standalone YAML, and a directory with `document.yaml` and `sections/`), with the same selection rule as `src/lib/server/catalogue.ts`. Images become data URLs. A refusal other than `missing` is an error shown to the user.
4. Reader state goes through the bridge's `getState`/`setState`, per tab; the browser and desktop builds keep `localStorage`. No `localStorage` access in the oculus build.
5. The source button calls `oculus.open({ file: { root, path } })` with the PDF under the folder its documents came from, and no page jump. A rejection is shown to the user.
6. Colours follow the oculus theme through `src/oculus/theme.css`, which maps the tokens oculus paints on the root element onto the palette of `src/app.css`, including the rules of `src/app.css` that hold literal colours, whatever the system colour scheme.
7. The README has a section "Run in oculus".
8. The browser and desktop builds behave as before: `src/lib/server/catalogue.ts`, `src/lib/desktop/library.ts` and `Reader.svelte` were changed only to share code or to take an injectable state store.
9. No oculus file is changed. No real ritual text appears in any file, test, report or output.
10. The gates of `.agents/building.md` (seven commands) pass.

## Premises checked against the tree

- oculus serves an app under a policy with `sandbox`, `default-src 'none'`, scripts from the app's address and `/apps/-/` only, `img-src` the app and `data:`: `/Users/axelfaes/workspace/research-hub/tools/oculus/DESIGN.md`, "Every app file is sent with this policy".
- A root app's `oculus.fs` root name is the root key in its own address `/apps/@<root>/<name>/<key>/`: `src/lib/state/system/apps/frame/methods.ts` `fsAddress` and `src/lib/data/helpers/files/apps/apps.ts` `appAddress` in the oculus tree.
- oculus's `oculus.js` paints the theme tokens on the root element and sets `color-scheme`: `src/lib/server/machine/apps/serve/oculus.js` `paint`.
- `SourceLink.svelte` is the only file of `src/lib` that imports `$app/*`.
